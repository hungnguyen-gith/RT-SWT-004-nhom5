The experimental results demonstrate that Pynguin consistently outperformed GPT-4o mini in terms of Branch Coverage, indicating that search-based test generation remains more effective than zero-shot LLM prompting for systematically exploring execution paths. Although GPT-4o mini achieved a high test generation success rate, the generated tests frequently failed to cover meaningful program branches, resulting in substantially lower testing effectiveness. These findings suggest that executable test generation alone is insufficient for producing high-quality unit tests without adequate execution guidance or feedback mechanisms.

This study compares GPT-4o mini and Pynguin in generating automated units test for Python functions with varying levels of cycle complexity. The results show that Pynguin achieved higher branch coverage than GPT-4o mini under the same setup. Furthermore, both methods had a 0% mutation rate, indicating that the findings indicate that higher branch coverage does not necessarily correspond to improved fault detection capability. This highlights a common limitation between LLM-based and traditional test generation methods: improving test quality and considering execution context still require further attention in future studies.
