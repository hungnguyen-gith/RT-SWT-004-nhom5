This study empirically compared GPT-4o mini and Pynguin for automated unit test generation on a benchmark of 50 Python functions. The experimental results showed that Pynguin substantially outperformed GPT-4o mini in terms of Branch Coverage, achieving a median coverage of 50% compared with 0% for GPT-4o mini. Statistical analysis using the Mann–Whitney U test and Cliff's Delta (values to be reported) should be used to determine the statistical significance and practical effect of this difference.

Although GPT-4o mini successfully generated executable test suites for most benchmark functions, the generated tests rarely exercised meaningful execution paths, resulting in poor structural testing effectiveness. Both approaches obtained a Mutation Score of 0%; however, this outcome was mainly attributed to the current xfail wrapping issue in the mutation-testing pipeline rather than the intrinsic quality of the generated tests.

These findings indicate that search-based test generation remains more effective than zero-shot prompting for automated Python unit testing under the evaluated setting. Future work should resolve the mutation evaluation issue and investigate advanced prompting strategies or hybrid approaches that combine LLMs with search-based testing techniques.
