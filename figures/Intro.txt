Writing unit tests manually is time-consuming and error-prone, as developers must design test cases that cover diverse execution paths, boundary conditions, and exceptional scenarios. Under practical development constraints, unit testing is often insufficiently performed, resulting in lower test quality and increased maintenance costs.

Large Language Models (LLMs) have recently attracted significant attention in software engineering due to their strong capabilities in understanding and generating source code. Recent studies have applied LLMs to various software engineering tasks, including code completion, bug detection, program summarization, and automated software testing. Among these applications, automated unit test generation has emerged as one of the most actively investigated research topics. In real-world projects, developers need to design test cases that include various execution scenarios, boundary cases, and exceptions—something difficult to achieve manually under time constraints, which reduces software quality and increases maintenance costs later on. Previous studies have demonstrated that LLMs can generate executable unit tests with limited human intervention while exhibiting promising code comprehension and reasoning capabilities. Researchers have proposed various techniques, including prompt engineering, feedback-guided refinement, and multi-agent collaboration, to further improve test generation quality. Previous empirical studies have reported promising results using evaluation metrics such as Branch Coverage, Mutation Score, and Test Generation Success Rate.

Despite its widespread application in this field, several gaps remain. Different studies on datasets, metrics, recommendation strategies, and test setups make direct comparisons difficult. Most existing work also focuses on advanced recommendation techniques or custom LLM frameworks, while lightweight LLMs in simple zero-shot setups receive less attention. More importantly, there is currently very little empirical evidence comparing GPT-4o mini with Pynguin—a widely used tool for automated unit testing for Python—in a consistent evaluation setup. Consequently, further empirical evaluation is required to better understand the effectiveness of GPT-4o mini for automated Python unit test generation.

To address these research gaps, this study evaluates GPT-4o mini for generating zero-shot unit tests on Python functions with varying levels of cycle complexity. The generated tests were evaluated using Branch Coverage, Breakpoints, Precision, and Test Generation Time. The generated test suites were compared with those produced by Pynguin under an identical experimental setting:
•	Experimental evaluation of GPT-4o mini for generating untrained unit tests on Python functions with different cycle complexities.

•	Comparison between GPT-4o mini and Pynguin using Branch Coverage, Breakpoints, Precision, and Test Generation Time.

•	Discussion of the strengths and weaknesses of automated unit test generation methods based on LLM versus traditional methods for Python.
